# EVE Alert

面向 EVE Online 的屏幕 RGB 识别与告警桌面应用。通过监测指定画面区域的颜色变化，为多个角色分别发出告警、告警解除和提醒。

项目聚焦画面颜色识别、监控配置和通知送达。使用 Tauri 2、Rust、React、TypeScript 和 MUI（Material Design）构建，当前屏幕捕获实现面向 Linux，依赖 XDG Desktop Portal 与 PipeWire。

## 功能与识别规则

- **多角色监控**：每个角色独立选择捕获来源、配置识别区域并维护识别状态；可分别启用或禁用，监控时仅处理已启用角色。
- **角色配置复用**：可复制为新角色，也可将当前角色的告警区域、三个提醒区域与各自 RGB 覆盖到已有角色。覆盖保留目标名称、来源授权及启用状态，复制后的区域数据独立。
- **区域与颜色配置**：截图框选、移动和八方向缩放选区，支持全屏编辑、缩放与平移；通过像素放大镜查看原始 RGB，也可手动输入坐标和多组 RGB。提醒的三个独立区域在同一个编辑页和全屏窗口中配置，同时显示不同颜色的选框。
- **界面主题**：支持浅色、深色和跟随系统；主题选择自动保存在当前 WebView 的本地存储中，不改变监控配置格式。
- **告警**：告警区域首次命中目标颜色时产生 `Warn`；持续命中不重复发送；全部目标颜色消失时产生一次 `WarnCleared`；再次出现时重新告警。
- **提醒**：区域 1 首次命中 RGB1 时产生 `Reminder`（`LastWave`）：“异常进入最后一波次”，并启动区域 2 的 RGB2 检测。区域 2 命中任意一种 RGB2 后开启区域 3 的 RGB3 检测；记录到 RGB3 后等待其消失。RGB1 消失，或记录后 RGB3 消失时，产生一次 `Reminder`（`Ended`）：“异常结束”。结束时清空本轮标记；如果 RGB1 仍在，必须等待它消失并重新出现才开始下一轮。
- **通知渠道**：声音、Linux 桌面通知、ntfy、SSE、反向 WebSocket 和 OneBot 11 私聊。
- **排查工具**：导出原始 PNG 截图，查看最近 100 条事件及捕获、网络、通知和声音错误。

区域内任意像素精确匹配任意一种配置颜色即视为命中，忽略 alpha；坐标包含起点与终点。每个来源最高交付 2 FPS，同时向 PipeWire 上游请求不超过 2 FPS，并在像素转换前跳过多余帧；静止画面不保证持续产生新帧。短于约 500 ms 采样间隔的画面变化仍可能漏检，调度延迟或来源不更新会延长间隔。界面颜色、缩放或布局变化后，应重新检查区域和取色配置。

为避免上游帧略早到达时被连续丢弃，接近发布期限的帧可提前最多 50 ms 转换并暂存一张自有图像，到期后才交付；每路邮箱仍只缓存最新一帧，不重复发布旧帧。采样时刻可能与旧实现不同，告警去重、提醒状态机、精确 RGB 与坐标规则保持不变。上游接受限帧时可减少截图渲染和下载；即使未接受，本地也会跳过多余转换，实际桌面收益需实测。

Debug 日志按来源每 5 秒汇总接收、有效、转换、跳帧、交付数量与速率，以及转换耗时和交付间隔；每次格式协商另记实际 `framerate` / `max_framerate`。Release 可在启动应用前设置 `EVE_ALERT_CAPTURE_DIAGNOSTICS=1` 启用捕获诊断。协商值缺失或超限时会警告并保留本地限速；格式无交集则报告捕获失败，不自动重连或重新打开选择器。诊断编号不含窗口标题或授权凭据；分享其他日志前仍需检查个人信息。实现与桌面验收范围见 [排查与优化记录](REMINDER.md#10-第一阶段实施记录2026-11-04)。

各角色状态独立。启动时未命中不会发送告警解除；捕获异常或区域越界也不视为解除。画面缩小导致区域越界时，暂停该角色的识别并重置提醒状态，直到区域重新落入画面，或停止监控后重新配置。

启动监控时区域 1 已命中 RGB1，会立即发送第一次提醒。同帧命中 RGB2 时立即开启区域 3 检测，若同帧也命中 RGB3 则立即记录。本轮开始前的 RGB2、开启区域 3 前的 RGB3 均不保留记录；开启后 RGB2 消失不会结束本轮，也不会关闭区域 3 检测。等待 RGB2 或 RGB3 时，RGB1 消失也会结束本轮；多个结束条件同时满足只发送一次结束提醒。停止监控或无效帧重置状态不会发送“异常结束”，下轮需重新命中前置条件。三个区域可独立框选或重叠，各自支持多种目标色，任意一种命中即视为对应 RGB 命中。帧率仍为最高 2 FPS，不新增延时或防抖；每轮仍发送两次提醒。新增区域仅在等待 RGB2 时扫描，RGB3 仅在前置命中后扫描，额外开销取决于新增区域大小；短于采样间隔的 RGB2 可能漏检，导致本轮无法开启区域 3 检测，RGB1 消失仍可结束本轮。

RGB3（原 RGB2）配置多个值时，任意一种出现就记录，无需所有颜色都出现。记录后，要求区域 3 中所有配置颜色均不存在，才由 RGB3 的消失触发“异常结束”；最初命中的颜色消失但其他配置颜色仍在，或颜色切换到另一个像素，都继续等待。例如配置 A、B、C，只有 A 出现也能记录；A 消失但 B 或 C 仍在不会结束，A、B、C 全部消失才结束。RGB1 消失仍是独立的结束条件。

## NixOS 安装

`flake.nix` 提供 `packages.x86_64-linux.eve-alert` 和默认软件包，当前支持 `x86_64-linux`。软件包以 Release 模式构建，包含前端资源、桌面入口和 WebKit / GStreamer 运行依赖，安装后通过 `eve-alert` 启动，无需进入开发环境。

在启用 Flakes 的 NixOS 上，进入仓库目录后可构建或安装当前源码；Git 仓库中的新增源码文件需先纳入 Git 跟踪：

```sh
# 构建并直接启动
nix build .#eve-alert
./result/bin/eve-alert

# 安装到当前用户的 profile
nix profile add .#eve-alert
eve-alert

# 也可临时运行，不安装到 profile
nix run .#eve-alert
```

使用 Flake 管理 NixOS 配置时，将仓库加入系统 flake 的 `inputs`（需先将软件包定义提交并推送到该仓库）：

```nix
inputs.eve-alert.url = "github:Ecamika/eve-alert";
```

在通过 `specialArgs = { inherit inputs; };` 接收 flake 输入的 NixOS 模块中添加：

```nix
{ inputs, pkgs, ... }:
{
  environment.systemPackages = [
    inputs.eve-alert.packages.${pkgs.stdenv.hostPlatform.system}.eve-alert
  ];
}
```

随后按现有流程执行 `sudo nixos-rebuild switch --flake /你的系统配置目录#主机名`。若使用 Home Manager，可将同一个软件包加入 `home.packages`。

屏幕捕获仍需桌面会话提供 PipeWire、XDG Desktop Portal 及支持 ScreenCast 的 Portal 后端，首次选源时在系统对话框中授权。软件包沿用开发环境的 X11 与 WebKit 兼容默认值，可通过启动前设置 `GDK_BACKEND` 和 `WEBKIT_DISABLE_DMABUF_RENDERER` 覆盖。配置保存在 `~/.local/share/eve-alert/`，详见下文。

更新 `pnpm-lock.yaml` 后，需重新计算 `flake.nix` 中 `pnpmDeps.hash`：临时设为 `pkgs.lib.fakeHash`，执行 `nix build .#eve-alert.pnpmDeps`，将哈希不匹配错误中的 `got: sha256-…` 写回，再重新构建。Rust 依赖直接从 `src-tauri/Cargo.lock` 读取。

## 开发与启动

仓库通过 `flake.nix` 描述 NixOS 开发环境。以下命令应在已配置的项目开发环境中执行：

```sh
pnpm exec tauri dev
```

仅运行 `pnpm dev` 可查看前端，端口为 `4567`；捕获、配置存储和监控需要 Tauri 桌面进程提供的 IPC。

Tauri 产品名为 `eve-alert`，应用标识符为 `dev.ecamika.project.eve-alert`。`frontendDist` 为相对 `src-tauri/` 的 `../dist/`，与前端构建输出对应。

## 使用流程

1. 添加角色并填写名称，通过角色列表中的开关选择本次启用的角色。名称用于标识事件，不会自动查找同名游戏窗口；新增角色默认启用。启用状态与其他配置一样，停止监控后可调整，保存后保留。
2. 点击“获取 / 恢复来源”，在系统屏幕共享选择器中选择该角色的 EVE 窗口或所在屏幕，确认共享授权。每个角色分别操作；后续优先恢复已保存的授权。更换窗口或屏幕时使用“重新获取来源”。
3. 收到首帧后点击“刷新截图”，配置“告警区域”；再打开“提醒配置”，在同一张截图上通过“区域 1 / RGB1”“区域 2 / RGB2”和“区域 3 / RGB3”切换当前编辑对象，分别框选三个区域、设置各自颜色。紫色选框对应区域 1，橙色选框对应新增的前置区域 2，绿色选框对应区域 3（原区域 2），实线及控制点表示当前编辑对象，虚线表示其他区域。切换“取色”后点击画面取色，仅添加到当前区域；每个区域至少需要一种颜色。全屏编辑也可直接切换三个区域。
4. 按需添加报告方式，点击“保存配置”，再“开始监控”。未添加报告方式时仍会记录事件。
5. 修改区域、颜色或其他配置前先停止监控。“停止监控”释放全部捕获资源，保留来源恢复凭据，下次启动监控时尝试恢复。

已连接的角色需先释放来源才能改名。恢复凭据按角色名称关联，改名后需要重新选源。“释放来源”停止当前捕获，但保留凭据。

复用配置时，先选中提供配置的角色，点击“覆盖到其他角色”，选择目标后点击“确认覆盖”，再保存配置。仅替换目标角色的四个区域与 RGB，保留目标名称、来源授权和启用状态；请刷新目标角色截图，检查区域是否适合其画面。“复制为新角色”会另建一份配置，新角色需单独选择来源。

至少启用一个角色才能启动监控。禁用角色仍可在停止监控时配置或预览截图；启动监控时会释放禁用角色的预览捕获，仅为已启用角色获取或恢复来源、检查画面并执行识别。禁用不删除角色配置或恢复凭据，也不会发送告警解除或异常结束；重新启用后下一次启动监控会从初始状态识别。

截图编辑工具支持以下操作：

- **框选**：在选区外拖动创建新区域，在选区内拖动移动；拖动八个控制点调整大小。按住 Shift 拖动可在选区内重新框选。画布聚焦后，方向键移动 1 像素，按住 Shift 移动 10 像素；Esc 取消当前拖动。
- **取色**：切换“取色”后点击画面，将原始像素的 RGB 添加到当前区域，自动忽略重复颜色。放大镜与颜色读数来自原始截图，不受选框或遮罩影响；最后一种颜色不能删除。
- **缩放与平移**：使用放大、缩小、1:1、适应按钮，支持 12.5%–1600% 缩放；选择“平移”工具或按鼠标中键拖动画布，也可滚动查看。
- **精确调整**：直接编辑起点和终点坐标，输入限制为截图内的整数，自动保持起点不大于终点；已有配置超出新截图时显示提示，请重新框选或调整。
- **全屏编辑**：点击全屏按钮扩大编辑空间，退出按钮或 Esc 返回。监控期间锁定配置编辑，仍可查看、缩放和平移截图。

右上角可选择浅色、深色或跟随系统主题。仅运行前端开发服务器时会显示浏览器预览提示；桌面专用操作不可用。

声音由桌面 WebView 播放，同类音频播放期间不叠加。音频文件上限为 20 MiB，支持格式取决于 WebView 与系统解码器；告警解除使用“提醒 / 告警解除音频”。

## 配置、授权与截图

配置为 JSON，包含角色列表 `characters` 和通知配置 `report_methods`。前端启动时加载配置，保存时校验并通过同目录临时文件替换。无配置时显示空列表，首次保存才创建配置文件。

角色新增布尔字段 `enabled`：`true` 为启用，`false` 为禁用。旧配置缺少该字段时按启用读取，保存时写入明确的启用状态。监控启动时筛选角色，不删除配置文件中的禁用角色。

提醒区域独立保存 `start`、`end` 和 `rgb`：`reminder_now_region` 对应区域 1 / RGB1，新增 `reminder_gate_region` 对应前置区域 2 / RGB2，原 `reminder_enemy_region` 改为区域 3 / RGB3，其坐标和颜色保持不变。读取缺少新增字段的旧配置时，将原区域独立复制为区域 2 的初始值，以保持旧配置的检测行为；请在界面为新增区域 2 单独框选、取色并保存。保存后写入新增字段，不修改原配置路径或授权凭据。`Warn`、`WarnCleared` 和 `Reminder` 的外部事件协议保持不变。

| 构建模式 | 配置路径 |
| --- | --- |
| Debug（`debug_assertions`） | 编译时项目根目录下的 `reporting.json` |
| Release | `~/.local/share/eve-alert/reporting.json` |

Debug 路径不依赖启动工作目录；Release 使用 `HOME/.local`。同目录的 `reporting-capture.json` 单独保存捕获恢复凭据，`screenshots/` 保存导出的截图，文件名包含角色名称和时间戳。开发配置、凭据和截图已加入 Git 忽略规则；配置可能含访问令牌，凭据文件不应分享或提交。

授权恢复依赖支持 ScreenCast v4 持久化能力的 Portal 后端。系统可能拒绝持久化或要求再次确认；应用在恢复前移除旧凭据，成功后保存新凭据，失败或取消后可能需要重新授权。

应用不自动迁移旧版配置目录，也不导入参考实现的 `settings.toml`。已有配置需手动放入当前配置路径；捕获授权以系统实际确认结果为准。

## 外部通知接入

### SSE

在前端配置监听 IPv4 地址与端口，监控启动时绑定服务。客户端连接 `http://监听地址:端口/events`：

```text
data: ["EVE - 角色1","EVE - 角色2"]

data: {"type":"Warn","title":"EVE - 角色1"}

data: {"type":"WarnCleared","title":"EVE - 角色1"}

data: {"type":"Reminder","title":"EVE - 角色1","stage":"LastWave","message":"异常进入最后一波次"}

data: {"type":"Reminder","title":"EVE - 角色1","stage":"Ended","message":"异常结束"}
```

首条数据为本次监控已启用的角色列表，后续为事件，每 5 秒发送保活注释；支持跨域 GET。可接入独立的 [eve-reporting-client](https://github.com/EVE-Little-God-People-Club/eve-reporting-client)。外部客户端需处理 `WarnCleared` 才能展示告警解除。

`Warn`、`WarnCleared` 的字段不变；`Reminder` 保留 `type` 和 `title`，新增 `stage`、`message`，每轮发送进入和结束两次事件。忽略未知字段的旧客户端仍可接收，但只会显示通用提醒；需要适配新字段才能区分两个阶段。严格校验 JSON 字段的客户端需同步更新。反向 WebSocket 使用相同协议。

### ntfy

添加“ntfy”，填写服务器地址（默认 `https://ntfy.sh`）、主题和可选访问令牌；在 ntfy 客户端订阅相同服务器与主题。支持自建服务器。

应用以 JSON 发布事件，标题与正文包含状态和角色名称；告警优先级为 4，其余为 3。每次事件发送一次 HTTP 请求，失败时在界面显示错误，不自动重试；停止监控会取消尚未完成的请求。

### 反向 WebSocket

设置 `ws://` 或 `wss://` 地址，应用主动连接并发送与 SSE 示例相同的事件 JSON。可配置持续重连与重试间隔，连接中断期间不保证事件交付。

使用参考实现的独立 `onebot-reporting-bot` 时，填写该服务的 `/ws` 端点。

### OneBot 私聊

添加“OneBot 私聊”，填写 OneBot 11 正向 WebSocket 地址、可选访问令牌和私聊目标 ID，无需单独部署中转机器人。

应用调用 `send_private_msg`，告警文本保留 `Warn 角色名称`、`WarnCleared 角色名称`；提醒文本为 `Reminder 角色名称：异常进入最后一波次` 或 `Reminder 角色名称：异常结束`。依赖完整提醒文本解析的接入方需适配此变化。桌面通知、ntfy 与前端事件记录同样显示具体阶段消息；两次提醒沿用现有提醒音频及同类音频不叠加规则。断线每 5 秒重连。告警去重由识别状态变化统一处理；旧配置字段 `warn_spacing_secs` 可被读取但不再生效。

## 验证范围

Rust 测试覆盖 RGB 精确匹配、像素边界、告警与提醒状态迁移、配置错误、启用状态兼容与监控筛选、授权恢复存储、事件协议及部分输出行为；捕获和插件基础设施另有模块测试。`pnpm test` 使用 Node 内置测试框架验证截图缩放坐标映射、反向拖动、选区移动与缩放边界、无效区域，以及角色配置覆盖的身份保留与数据隔离；当前未配置组件测试框架或覆盖率门槛。

真实捕获需在 Linux 桌面会话中授权，并用实际 EVE 画面验证告警区域及三个提醒区域、多角色状态及停止后的资源释放。声音、桌面通知和外部推送需结合实际桌面与服务联调。编译或自动测试通过不代表这些联调已完成。
